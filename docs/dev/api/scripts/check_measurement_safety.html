scripts.check_measurement_safety

Avisa si un cambio toca una zona protegida de la medicion (docs/dev/ZONAS_PROTEGIDAS.md).

Compara el arbol de trabajo (o lo que esta en el indice, o los commits desde una revision) contra la lista de zonas protegidas (ZONES, la fuente unica: una prueba la mantiene alineada con el documento) y dice CLARAMENTE que archivos protegidos cambiaron y de que manera:

  • codigo cambiado / archivo cambiado: cambia el comportamiento; invalida o puede invalidar la medicion.
  • fijado por hash: app/llm/prompts.py y app/llm/market_features.py; ni un byte (ni un comentario), porque una prueba los fija.
  • parametro protegido: cambio el valor por defecto de una variable de configuracion en app/config.py, .env.example, docker-compose.yml o scripts/start_bot.ps1.
  • esquema: cambio el DDL de una tabla de la medicion (app/persistence/database.py). Una columna nueva es aditiva (nivel REVISAR); cambiar o quitar lo existente es PROTEGIDO.
  • solo documentacion: cambian docstrings, comentarios o espacios; el AST es el mismo.
  • zonas REVISAR: no invalidan la medicion por si solas, pero pueden mostrar resultados antes de tiempo, detenerla, degradarla o cambiar el entorno donde corre.

Es una herramienta de LECTURA: solo ejecuta git y lee archivos del repositorio. No importa app, no lee .env, no abre la base y no escribe nada. Solo ve el repositorio: un cambio hecho a mano en tu .env real no se detecta (para el modelo usa scripts/measurement_identity.py).

python scripts/check_measurement_safety.py                  # arbol de trabajo contra HEAD
python scripts/check_measurement_safety.py --staged         # solo lo que entraria al commit
python scripts/check_measurement_safety.py --since <commit> # todo lo hecho desde ese commit
python scripts/check_measurement_safety.py --since-measurement
python scripts/check_measurement_safety.py --list           # imprime las zonas y sale

Codigos de salida: 0 sin cambios protegidos (o solo de documentacion); 1 hay cambios PROTEGIDOS (con --strict, tambien si hay algo para revisar); 2 error de uso o de git.

Gancho pre-commit opcional (NO se instala solo; ver docs/dev/ENTORNO_DESARROLLO.md): un archivo .git/hooks/pre-commit que llame a este script con --staged.

@dataclass(frozen=True)
class Finding:

Un hallazgo: un archivo o un parametro protegido que cambio.

Attributes:
  • level: nivel del hallazgo (PROTEGIDO o REVISAR).
  • zone: titulo de la zona (o de las zonas, separadas por /).
  • path: archivo (o archivo: VARIABLE para un parametro).
  • kind: de que manera cambio (KIND_*).
  • detail: texto extra (valor anterior y nuevo, columnas, etc.).

def changed_paths(repo: pathlib.Path, base: str, *, staged: bool) -> dict[str, str]:

Los archivos que cambiaron respecto de una revision.

Arguments:
  • repo: raiz del repositorio.
  • base: la revision de comparacion (HEAD, un commit...).
  • staged: comparar solo lo que esta en el indice (lo que entraria al commit).
Returns:

ruta -> estado (A, M o D); los renombrados cuentan como borrado mas alta. Cuando no es staged incluye los archivos nuevos sin seguimiento (no ignorados).

Raises:
  • RuntimeError: si git falla (no es un repositorio, la revision no existe...).
Efectos:

Ejecuta git diff y git ls-files; no escribe nada.

  • base: la revision de comparacion.
  • staged: comparar solo el indice.
Returns:

Los hallazgos, ordenados por nivel, zona y ruta.

Raises:
  • RuntimeError: si git falla.
Efectos:

Ejecuta git y lee archivos del repositorio; no escribe nada.

Los commits desde base que tocaron alguno de esos archivos.

Arguments:
  • repo: raiz del repositorio.
  • base: revision de partida (excluida).
