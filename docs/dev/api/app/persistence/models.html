app.persistence.models

Modelos pydantic que reflejan las filas de la base de datos.

Cada modelo corresponde a una tabla (o a una vista de ella): Trade y ShadowTrade a trades y shadow_trades, SignalRecord a signals, RiskRejection a risk_rejections, OHLCVBar a ohlcv_cache, y los Backtest* a las tablas del backtest de la Fase 2. Los repositorios convierten filas SQLite en estos modelos; el resto del codigo trabaja con ellos y no con filas crudas.

class Side(enum.StrEnum):

Direccion de una operacion: LONG (compra) o SHORT (venta).

Coincide con el CHECK de las tablas.

LONG = <Side.LONG: 'LONG'>
SHORT = <Side.SHORT: 'SHORT'>
class TradeStatus(enum.StrEnum):

Estado de una operacion: OPEN (abierta) o CLOSED (cerrada).

Coincide con el CHECK de las tablas.

OPEN = <TradeStatus.OPEN: 'OPEN'>
CLOSED = <TradeStatus.CLOSED: 'CLOSED'>
class Trade(pydantic.main.BaseModel):

Una operacion de la cuenta paper (fila de trades).

Los campos opcionales son None mientras no aplican (una posicion abierta no tiene exit_price ni PnL). Los niveles sl_price, tp_price, trailing_distance, effective_stop, best_price y liq_price son los que el monitor de posiciones evalua en vivo; si falta uno, el monitor evalua solo los que existen. Los campos reconciliation_* marcan una reconciliacion fallida tras un reinicio (ver app/trading/position_monitor.py). ShadowTrade extiende este modelo.

class ShadowTrade(Trade):

Operacion sombra (subfase 3.5): una senal agrupada, simulada con margen ilimitado y con las mismas formulas de fees, slippage y funding que la cuenta paper, pero sin cupos ni margen disponible. contributing_strategies lista TODAS las estrategias que coincidieron en (simbolo, direccion, vela): el resultado se atribuye a cada una en el reporte. llm_decision es SIN_LLM hasta la subfase 3.6.
