app.persistence.database

Capa de persistencia: conexion aiosqlite, esquema SQL y migraciones de columnas.

SCHEMA contiene el DDL completo de la base (todas las tablas, indices y el disparador llm_decision_inmutable); Database.connect() lo ejecuta en cada arranque con CREATE ... IF NOT EXISTS, asi que una base existente solo recibe lo que le falta. Las columnas agregadas despues de la primera version de una tabla se migran con los diccionarios _*_MIGRATED_COLUMNS mediante ALTER TABLE ADD COLUMN (idempotente). El esquema tabla por tabla se documenta, generado desde este archivo, en docs/ESQUEMA_BD.md; la guia de como cambiarlo esta en docs/dev/MODELO_DATOS.md.

Efectos:

Crear una Database y llamar a connect() crea el directorio y el archivo de la base si no existen, activa WAL y escribe las tablas y columnas que falten. Sin red.

class Database:

Envoltorio fino sobre UNA conexion aiosqlite compartida por todo el proceso.

Se usa una sola conexion con un candado de escritura (_write_lock) porque SQLite no tolera bien escrituras concurrentes desde varias conexiones; para el volumen de Minerva (un bot, no multiusuario) basta. execute y execute_many toman el candado y hacen commit; fetch_one y fetch_all no lo toman (leen sobre la misma conexion).

Attributes:
  • path: ruta del archivo SQLite, o ":memory:" para una base volatil (pruebas).

conn: aiosqlite.core.Connection

La conexion aiosqlite abierta.

Raises:
  • RuntimeError: si todavia no se llamo a connect() (o ya se cerro).
async def connect(self) -> None:

Abre la conexion, configura SQLite y crea o completa el esquema.

Crea el directorio padre del archivo (salvo :memory:), usa aiosqlite.Row como fabrica de filas, activa journal_mode=WAL y synchronous=NORMAL (seguro con WAL: solo arriesga las ultimas transacciones en un corte de energia, no la integridad) y llama a init_schema().

Efectos:

Disco: crea el directorio y el archivo de la base si no existen. Escribe las tablas, indices, el disparador y las columnas migradas que falten. Sin red.

async def close(self) -> None:

Cierra la conexion si esta abierta; es idempotente.

Efectos:

Cierra el archivo SQLite (en modo WAL el ultimo cierre consolida el -wal).

async def init_schema(self) -> None:

Ejecuta SCHEMA y aplica las migraciones de columnas, bajo el candado de escritura.

Es seguro correrlo sobre una base ya poblada: nada se borra ni se reescribe. Para agregar una columna a una tabla existente hay que declararla en SCHEMA Y en el diccionario _*_MIGRATED_COLUMNS de esa tabla (ver docs/dev/MODELO_DATOS.md).

Efectos:

Escribe el esquema (CREATE ... IF NOT EXISTS) y ALTER TABLE ADD COLUMN para las columnas migradas de backtest_verdicts, trades, signals, shadow_trades y llm_logs que falten. Sin red.

async def execute(self, query: str, params: tuple = ()) -> aiosqlite.cursor.Cursor:

Ejecuta una sentencia de escritura y hace commit, bajo el candado de escritura.

Arguments:
  • query: sentencia SQL con marcadores ?.
  • params: valores de los marcadores, en orden.
Returns:

El cursor, ya confirmado: sirve para leer lastrowid y rowcount.

Efectos:

Escribe en la tabla que nombre query. Sin red.

async def execute_many(self, query: str, params_list: list[tuple]) -> None:

Ejecuta la misma sentencia para cada tupla de params_list en UNA sola transaccion.

Evita el fsync por fila al insertar en bloque (p. ej. una pagina de 200 velas); se detecto como cuello de botella real durante la corrida del backtest de la Fase 2. Con la lista vacia no hace nada.

Arguments:
  • query: sentencia SQL con marcadores ?.
  • params_list: una tupla de valores por fila.
Efectos:

Escribe en la tabla que nombre query, con un solo commit. Sin red.

Arguments:
  • query: consulta SQL con marcadores ?.

Returns:

Un aiosqlite.Row (acceso por nombre de columna) o None.

Lee la tabla que nombre query. Sin red.
