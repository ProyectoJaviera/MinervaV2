app.trading.real_money_report

Reporte de paso a dinero real (subfase 3.8, docs/FASE3_PLAN.md punto 8).

Solo RECOMIENDA. v1 es 100 % paper: este modulo no importa ningun backend de ejecucion ni cliente de red, nunca habilita nada, y su salida termina siempre diciendo que la decision es manual y requeriria una fase nueva.

Orden estricto (estructural, con test de que no se lee nada antes):

  1. compute_status + is_outcome_reveal_allowed (gate abierto Y registro oficial del veredicto). Si es falso: solo "que falta"; no se consulta trades ni ningun resultado.
  2. Se lee el registro oficial (verdict_record); si NO dice APORTA_VALOR la conclusion es "no pasar a dinero real" y no se evalua nada mas.
  3. Solo entonces se evaluan los criterios del brazo ejecutado (las operaciones REALES simuladas abiertas por el LLM, decision_source = LLM_APROBADA), mas los riesgos operativos medidos y la transferencia a las estrategias elegibles.

Los regimenes <30 / 30-100 / >=100 por lado de la fila 3.8 original se RETIRARON: la medicion 3.6 fija un unico punto de analisis (300 conglomerados efectivos por lado) y mostrar cifras antes contradice la regla de una sola mirada; el reporte usa solo el veredicto del registro oficial, que CITA (nunca recalcula).

Cada criterio devuelve PASA / NO PASA / SIN DATOS; la falta de datos nunca cuenta como "pasa". Criterio de rentabilidad (decidido el 2026-10-17): PF > 1,3 Y limite inferior del IC 95 % del PF > 1,0 (bootstrap por conglomerados).

def build_report( conn: sqlite3.Connection, *, settings: app.config.Settings, frozen_hash: str = '0fa0dd75a3fecdae36f3b77c8b7ec5d97d58a2238349283c61bfa7632188c777', allow_synthetic_for_tests: bool = False, docs_dir: pathlib.Path | None = None, log_file: pathlib.Path | None = None) -> RealMoneyReport:

Construye el reporte con un orden ESTRUCTURAL: nada lee resultados antes del registro.

1) Gate abierto Y registro oficial: si no, solo "que falta". 2) El veredicto oficial debe ser APORTA_VALOR: si no, "no pasar" y nada mas. 3) Solo entonces se evaluan los criterios del brazo ejecutado y los riesgos operativos medidos. SOLO RECOMIENDA: v1 es 100 % paper.

Arguments:
  • conn: conexion de solo lectura a una COPIA de la base.
  • settings: configuracion (umbrales).
  • frozen_hash: hash del prompt de la medicion; por defecto, el congelado.
  • allow_synthetic_for_tests: acepta otro hash solo con una base positivamente sintetica.
  • docs_dir: carpeta del registro oficial; por defecto, docs/ del repositorio.
  • log_file: log del bot para contar errores de reconciliacion, o None.
Returns:

El RealMoneyReport.

Raises:
  • ValueError: si el hash no es el congelado y no se pidio el modo sintetico.
  • SyntheticGuardError: si se pidio el modo sintetico y la base no lo es.
Efectos:

Lee llm_logs, shadow_trades, signals, system_state, asset_universe, contract_specs_cache, ohlcv_cache, paper_execution_log y docs/. Solo con el registro oficial en APORTA_VALOR lee trades.
